# 数据模型与接口草案

## 1. 核心数据对象

数据库选型：MySQL 8。

1. 用户：基础资料、手机号、实名认证状态、常用联系人、关联纪念馆。
2. 代办员：身份信息、资质状态、服务区域、服务类型、评级、接单状态、结算账户。
3. 服务：服务分类、服务名称、计费方式、基础价格、附加项、说明、退款规则、是否需审核。
4. 订单：订单编号、用户、服务、预约时间、地点、金额、支付状态、服务状态、派单状态、售后状态。
5. 报价单：需求说明、报价项、有效期、报价人、确认状态。
6. 履约凭证：订单、上传人、节点类型、图片视频、说明、时间、定位、水印信息。
7. 售后单：订单、申请原因、证据、客服结论、退款金额、处理状态。
8. 纪念馆：逝者姓名、关系、出生卒日、简介、图片、可见范围、审核状态。
9. 留言与祭拜记录：纪念馆、用户、内容、图片、审核状态、发布时间。
10. 结算单：订单、代办员应结金额、平台服务费、结算状态、结算时间。

## 2. 关键字段建议

### 2.1 订单表重点字段

订单类型、服务类型、城市、区域、联系人、联系电话、预约上门时间、当前状态、支付方式、退款状态、分账状态。

### 2.2 代办员表重点字段

接单范围、服务标签、评分、完成单量、投诉次数、冻结状态。

### 2.3 履约凭证表重点字段

节点类型、文件地址、经纬度、拍摄时间、备注、审核状态。

### 2.4 纪念馆表重点字段

公开范围、家属协作成员、纪念日提醒设置、审核结果。

## 3. 接口分组建议

### 3.1 用户端接口

登录授权、服务列表、服务详情、提交订单、提交询价、支付、订单查询、售后申请、纪念馆管理。

### 3.2 代办员端接口

实名认证、接单列表、接单确认、到场打卡、上传履约凭证、异常上报、完成任务、收入查询。

### 3.3 后台接口

服务管理、订单派单、代办员审核、内容审核、售后仲裁、财务结算、运营配置。

### 3.4 公共接口

上传文件、短信验证码、地图解析、消息通知、内容安全校验。

## 4. 接口边界原则

1. 订单和履约必须分离，避免订单对象过度膨胀。
2. 报价单单独建模，便于支持多轮报价。
3. 纪念馆与订单体系分离，避免内容产品和交易产品互相污染。
4. 所有敏感操作都要记操作日志，包括改价、退款、派单、冻结代办员。

## 5. 首版最小接口集合

1. 用户登录与实名。
2. 服务列表和详情。
3. 标准订单创建与支付。
4. 询价需求提交和报价确认。
5. 后台派单和代办员接单。
6. 到场打卡和履约上传。
7. 用户确认完成。
8. 售后申请与处理。
9. 纪念馆创建与审核。
